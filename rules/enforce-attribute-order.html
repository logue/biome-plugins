      #enforce-attribute-order

      warn

      HTML/Vue/JSX/Svelte attributes must be written in the prescribed group order, and static attributes must come before dynamic ones within the same group.

      #What it checks

      Adjacent attribute pairs whose group order is inverted. The rule covers .jsx, .tsx, and .vue files.

      #Why

      A consistent attribute order makes component markup scannable at a glance. The ordering below is derived from the Vue.js official style guide.

      #Group order (0 → 10)

      #GroupAttributes
      0Control Flow / Definitionv-is, v-for, v-if / v-else-if / v-else, v-show, v-cloak, v-pre, v-once; JSX: key; Svelte: {#each} / {#if}
      1Unique IDid, name
      2Two-Way Binding / Refv-model, v-slot, bind:*, ref
      3Classclass (Vue/HTML), className (JSX) — static before dynamic (:class)
      4Semanticalt, crossorigin, for / htmlFor, href, integrity, lang, rel, src, title, type
      5Sizingheight, width
      6Stylestyle
      7Otherremaining attributes, alphabetical
      8Accessibilityrole, aria-*
      9Datadata-*
      10Eventson* (JSX), @* (Vue), on:* (Svelte); v-html, v-text

      Within a group, write static values before dynamic bindings.

      #Examples

      #✗ Incorrect (JSX)

      // Event before className
<Button onClick={handleClick} className="btn">Click</Button>

// className before id
<div className="card" id="main-card" />

// aria before className
<nav aria-label="main" className="nav" />

      #✓ Correct (JSX)

      <Button className="btn" onClick={handleClick}>Click</Button>
<div id="main-card" className="card" />
<nav className="nav" aria-label="main" />

      #✗ Incorrect (Vue)

      <!-- Event before class -->
<button @click="handleClick" class="btn">Click</button>

<!-- Dynamic :class before static class -->
<div :class="dynamicClass" class="base-class" />

<!-- aria before class -->
<nav aria-label="main navigation" class="nav" />

      #✓ Correct (Vue)

      <button class="btn" @click="handleClick">Click</button>
<div class="base-class" :class="dynamicClass" />
<nav class="nav" aria-label="main navigation" />

      #Limitations

      GritQL is a pattern-matching language, not an imperative one. This rule can only detect adjacent out-of-order attribute pairs. Non-adjacent violations (e.g., three or more attributes where the first and third are swapped) are not detected. Full multi-attribute ordering will require native Biome support in a future release.
